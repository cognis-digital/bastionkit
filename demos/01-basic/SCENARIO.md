# Demo 01 — Assessing and hardening a namespace

This scenario shows `bastionkit` finding baseline gaps in an under-hardened
namespace, then passing a hardened one generated by the tool.

## Run it

```bash
# The insecure namespace fails the baseline (critical + high findings):
python -m bastionkit assess demos/01-basic/insecure
python -m bastionkit assess demos/01-basic/insecure --format sarif --out r.sarif

# The hardened namespace passes:
python -m bastionkit assess demos/01-basic/hardened

# Regenerate the baseline scaffold yourself:
python -m bastionkit generate --namespace secure-zone
```

## `insecure/` — what it should catch

A `payments` namespace with a deliberately dangerous Deployment and RBAC:

| Domain        | Issue                                                            | Severity |
|---------------|------------------------------------------------------------------|----------|
| RBAC          | `ClusterRoleBinding` to `cluster-admin` for the default SA       | critical |
| Workload      | container runs `privileged: true`                                | critical |
| RBAC          | `ClusterRole` with wildcard verbs/resources/apiGroups            | high     |
| Network       | no default-deny NetworkPolicy                                    | high     |
| Pod security  | namespace not labelled `enforce=restricted`                      | high     |
| Workload      | `hostNetwork: true`; `hostPath` mount; root; privilege-escalation| high     |
| Resources     | no ResourceQuota / LimitRange                                    | medium   |
| ServiceAccount| token automount not disabled                                    | medium   |

Because critical/high findings are present, the process exits non-zero,
failing any CI gate that wraps it.

## `hardened/` — what it should pass

`baseline.yaml` is the bundle emitted by `bastionkit generate --namespace
secure-zone`: a restricted-labelled Namespace, a default-deny NetworkPolicy
(plus a scoped DNS-egress allow), ResourceQuota, LimitRange, a least-privilege
read-only Role + RoleBinding, a no-automount ServiceAccount, and a
ValidatingAdmissionPolicy stub. `workload.yaml` is a fully hardened Deployment.
Together they score 100/100 and exit zero.
